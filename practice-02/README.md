## 3. Функции, ссылки и копирование

Прогноз записан до первого запуска исходного файла. Исходный пример был запущен,
затем исправлен пропуск `return` и повторён запуск. Прогнозы подтвердились.

| № | Прогноз до запуска | Фактический результат | Причина |
|---:|---|---|---|
| 1 | `5` (number); `"23"` (string) | `5` (number); `"23"` (string) | `+` складывает числа, но при строковом аргументе выполняет конкатенацию. |
| 2 | `undefined`; после исправления — `16` (number) | До исправления: `undefined`; после: `16` (number) | Фигурные скобки задают тело функции, в котором нужен явный `return`. |
| 3 | `5` (number); `true` (boolean) | `5`; `true` | `product` и `alias` указывают на один объект: изменение через одно имя видно через другое. |
| 4 | `7` (number); `false`; `true` | `7`; `false`; `true` | Spread создаёт новый массив, но вложенный объект остаётся общим. |
| 5 | `3 8 3` (числа); `false` | `3 8 3`; `false` | Более позднее свойство перекрывает раннее; новый объект не равен исходному по ссылке. |
| 6 | `"Без названия"`; `"Без названия"`; `null`; `""` | Те же значения; последний вывод — пустая строка | Значение по умолчанию применяется только при отсутствии аргумента или `undefined`, но не при `null` и `""`. |

**Исправление эксперимента 2:** выражение `value * value;` заменено на
`return value * value;`. Раньше вычисление выполнялось, но его результат
не возвращался вызывающему коду. В итоговом файле `square(4)` возвращает 16.
Остальные эксперименты сохранены без изменений.

## 4. Модель данных и функции

| Поле | Правило |
|---|---|
| `id` | Положительное безопасное целое число: `Number.isSafeInteger(id)` и `id > 0`. В списке уникально. Строка в число не преобразуется. |
| `title` | Строка длиной 1–100 после `trim()`. Краевые пробелы удаляются, внутренние сохраняются. Длина определяется через `.length`. |
| `completed` | Только boolean. При создании — `false`. |
| `priority` | Только `low`, `medium` или `high`. По умолчанию — `medium`; `null` считается ошибкой. |

| Функция | Результат |
|---|---|
| `createTask` | При успехе `{ ok: true, task }`; при ошибке `{ ok: false, error }`. Каждый успешный вызов создаёт новый объект. |
| `findTaskById` | Найденный исходный объект либо `undefined`. Используются `find` и строгое равенство. |
| `getPendingTasks` | Новый массив невыполненных задач через `filter`, в исходном порядке. |
| `getTaskTitles` | Новый массив названий через `map`, в исходном порядке. |
| `getTaskStats` | Числовые поля `{ total, completed, pending, progress }`. Для пустого массива все поля равны нулю. |
| `addTask` | Создание через `createTask`, проверка уникальности и добавление в конец через spread массива. |
| `setTaskCompleted` | Проверка id и boolean, обновление только `completed` через `map` и spread объекта. |
| `renameTask` | Проверка id и названия, обновление только очищенного `title` через `map` и spread объекта. |
| `removeTask` | Проверка id и наличия записи, удаление через `filter` с сохранением порядка. |

Четыре операции изменения возвращают `{ ok: true, tasks }` с новым массивом
при успехе либо `{ ok: false, error }` при отказе. Ожидаемые ошибки не выбрасывают
исключение. Даже повторная установка прежнего статуса или названия создаёт
новый массив и новый объект выбранной записи.

По контракту `tasks` — корректный массив задач с уникальными id. Произвольные
объекты, `tasks = null` и разреженные массивы не входят в обязательный контракт.

**Распределение ответственности:**

- [src/data.js](./src/data.js) — общий набор, номер варианта и шесть собственных задач.
- [src/task-service.js](./src/task-service.js) — девять прикладных функций и общие проверки id/названия. Вывода и глобального изменяемого списка нет.
- [src/main.js](./src/main.js) — сценарии, вывод, обработка отказов и подтверждение сохранности исходных данных.
- [checks.js](./checks.js) — 35 проверок из комплекта и четыре собственные проверки через `node:assert/strict`.
- [examples/functions-and-references.js](./examples/functions-and-references.js) — шесть учебных экспериментов.

**Почему id не равен индексу:** id — постоянный идентификатор задачи, индекс —
позиция в массиве. Например, задача id 4 стоит на позиции 1; после удаления
соседней задачи её идентификатор сохраняется, а позиция может измениться.

**Почему прогресс остаётся числом:** неокруглённое значение пригодно для дальнейших
вычислений. `toFixed(1)` возвращает строку, поэтому применяется только при выводе
в `main.js`. Для пустого списка выводится `Задач пока нет`, без процента.
В функции вывода сводки используется деструктуризация её четырёх полей.

**Что копируется:** новый массив создаётся при каждой успешной операции изменения;
при переименовании или смене статуса копируется ещё и выбранная задача.
Неизменённые записи можно использовать повторно. Все поля модели примитивные,
поэтому spread объекта достаточно для сохранения независимых значений его полей.

## 9. Вывод

В ПР1 обрабатывались отдельные числовые переменные. В ПР2 задачи представлены
объектами в массиве, а операции оформлены функциями с определёнными аргументами
и результатами. Данные, прикладные операции и консольный сценарий разделены
на ES-модули с `import` и `export`.

Вызвавшая сторона проверяет `result.ok` и принимает `result.tasks` только после
успеха. Ошибка возвращается как данные и не прерывает следующие действия.
`find`, `filter` и `map` используются для поиска, отбора, получения названий
и обновления записей. Spread позволяет сохранять предыдущие состояния.

Пропущенный `return` в стрелочной функции показал различие между вычислением
выражения и возвратом значения. Эксперимент с копией массива показал, почему
одного `[...tasks]` недостаточно при изменении полей вложенной задачи.
Сохранность данных подтверждена сравнением полей и ссылок, проверкой цепочек
операций и вызовами функций с замороженными входными объектами.
